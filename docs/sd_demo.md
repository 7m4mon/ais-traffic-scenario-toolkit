# Bluepill単体SDデモ

送信器のSD対応ファームウェア用に、他船AISと自船GPSを同期再生する `demo.bin` を生成します。
このツールキットにはRFファームウェアは含めません。送信器側の実装は
[AIS Plotter Test Interface](https://github.com/7m4mon/bluepill-adf7021-ais-interface) を参照してください。

## Bluepillの実容量

2026-11-03時点のC8向け軽量版は56,836バイト、グローバルRAM 9,080バイトです。
実チップがSTM32F103C8T6なら、IDEもSTM32F103C8を選びます。
8KBのSTM32duinoブートローダを使う場合、スケッチの実上限は **57,344バイト** です。
旧コアのIDE表示はこの8KBを差し引かないため、使用率だけでは判断できません。
詳細診断は `AIS_VERBOSE_DIAGNOSTICS=0` で短縮しています。SD・GPS・USB・RFの機能は維持します。

## カードの準備

FAT16/FAT32のmicroSDカードを使用します。exFATには対応しません。

```powershell
python .\tools\ais_scenario_sd_export.py --timeline .\timeline\exhibition_gauntlet.jsonl --output .\sd_card\demo.bin --name "EXHIBITION DEMO"
```

`sd_card\demo.bin` をカードのルートに `demo.bin` という名前でコピーします。
必要なら `--replay-speed 2` で2倍速、`--channel B` で全メッセージのRFチャンネルをBにします。
通常は等速・チャンネルAです。シナリオの最終時刻から1秒分の間隔を含めてループします。

## 起動時の動作

1. **電源OFFでカードを挿入・交換**します。
2. 起動時にカードを初期化し、`demo.bin` の全レコードとCRC32を検証します。
3. 正常なら自動で繰り返し再生し、OLEDに名前、経過時間、ループ番号、送信数を表示します。
4. カードがない・初期化失敗・ファイルなし・不正ファイルの場合はUSB入力モードになります。
5. 再生中の読み取り異常・フレーム生成異常・PLLロック失敗ではデモを停止し、USB入力モードへ戻ります。

カードの再検出はリセット／次回起動時だけです。USB接続先のPCがなくても起動します。
デモ中はUSBからのAIS入力を破棄し、混在を防ぎます。デバッグUARTの `0` でデモを停止して
USB入力へ戻せます。再開はリセットです。デモ中の手動操作は `?`・`s`・`0` に限定します。

配線はSDのCS=PB12、SCK=PB13、MISO=PB14、MOSI=PB15、VCC=3.3V、GND共通です。
**自船GPS出力はUSART3 TX=PB10、38400bps・8N1です。送信LEDはPB5へ移動します。**
前のAIS専用版でLEDをPB10に移した場合も、今回PB5へ移してください。
USART3 RX=PB11は未接続です。RF7021とOLEDの配線は変えません。

## プロッタの差動NMEA入力への接続

PB10は3.3V UART信号なので、NMEAのIN+/IN-には直接つなぎません。
3.3Vロジック対応のUART→RS-422送信回路／モジュールを追加します。

```text
PB10 (USART3 TX) ── 変換回路のロジック入力
Bluepill GND    ── 変換回路のロジック側GND
                   変換回路のTX+ ── プロッタ IN+
                   変換回路のTX- ── プロッタ IN-
```

モジュールの電源はその製品の仕様に従います。送信許可端子がある場合は送信を有効にします。
`A/B` の表記だけでは極性を確定せず、そのモジュールの説明書でTX+/TX-との対応を確認します。
差動の2本はツイストペアにします。プロッタ側も入力速度38400bpsと外部GPSの使用を設定します。
信号GNDやシールド、終端の接続はプロッタの説明書に従ってください。

送信ICの例は[AM26LV31E](https://www.ti.com/product/AM26LV31E)です（3.3V動作のRS-422ドライバ）。
絶縁が必要な機器・配線条件では、絶縁型の変換器を使用します。

## 制限

- 自船RMC/GGA/HDTと他船AISを同じ経過時刻でスケジュールします。
  同時刻では自船の出力開始を優先します。RFとシリアルの伝送時間による差は残ります。
- 自船NMEAは38400bpsの送信キューで流します。過負荷でキューがあふれた場合はデモを停止します。
  `--ais-only` を付けると従来どおり自船出力を除外できます。
- 合成GPSの日時は生成時のUTCから進みます。`--start-utc 2026-10-25T00:00:00Z` で指定可能です。
  記録済みの明示的な日時は維持します。日時・AISの秒フィールドはループごとに同じ値を繰り返します。
  RTCによる現在時刻への差し替えはしません。旧AIS専用ファイルには自船データがないため再生成してください。
- 船名・船種のMessage 24はPC再生と同じ条件で追加します。`--static-interval 0` で無効にできます。
- 各AISペイロードは最大600ビットです。端数は末尾の予備0ビットでオクテット境界へ揃えます。
  長すぎる安全メッセージは生成エラーになります。
- 合成シナリオの安全メッセージは完全なペイロードを保存できます。
  ログ由来の未結合の分割AIVDMは明示的に拒否します。
- ループ周期は最大24時間です。送信は1件ずつ行います。同時刻の複数メッセージは順番に送信し、
  処理能力を超えるデータ量や高速再生では予定時刻より遅れます。
- RF経路は既存の閉じた試験環境で使用してください。

## AISDEMO2形式

すべての整数はリトルエンディアンです。ヘッダは48バイトです。

| オフセット | サイズ | 内容 |
|---|---:|---|
| 0 | 8 | ASCII `AISDEMO2` |
| 8 | 4 | ループ周期ms、1〜86,400,000 |
| 12 | 4 | レコード数、1以上 |
| 16 | 4 | 本文バイト数 |
| 20 | 4 | 本文のCRC32（Python `zlib.crc32`） |
| 24 | 24 | ASCII名、最大23文字＋NUL |

各レコードは `時刻ms:uint32 / ビット数:uint16 / チャンネル:uint8 / 種別:uint8 / ペイロード` です。
種別0はAIS、チャンネルはASCIIの `A` または `B` です。
AISペイロードはフィールドのMSBから詰めたバイト列です。HDLCのビット順変換、FCS、
ビットスタッフィング、NRZIは送信器が実施します。

種別1は自船NMEA、チャンネルは `-`、ペイロードはCR/LFを除くASCII文（最大80バイト）です。
ビット数フィールドには文字数×8を格納します。送信器がCR/LFを付加します。
RMC/GGA/HDTのプレフィックス、印字可能ASCII、NMEAチェックサムも起動時に検証します。

時刻は0以上・ループ周期未満で昇順（同時刻可）、AISビット数は40〜600かつ8の倍数です。
ファイルサイズ、レコード数、時刻順、上限、チャンネル、種別、CRCを起動時に検証します。
新ファームウェアは旧 `AISDEMO1`（種別0のみ）も読み込めます。
